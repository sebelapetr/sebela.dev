# harness

The agent harness of this repository: what lets coding agents work through a phase of GitHub issues unattended, each issue in its own worktree, while the owner reviews one pull request per phase. Plain Node, no dependencies; `node --test harness/` runs its tests without `pnpm install`.

| Part                            | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run-phase.sh`, `run-phase.mjs` | The phase loop: starts the orchestrator once per issue, waits out usage limits, retries a safeguard stop once, labels failing issues `agent-retry` and `agent-failed`, logs the spend line of every iteration, stops when the steward says so and ends every process the run started, keeps private paths out of its issue notes, says what the phase end left                                                                                                                                                                                                                                                                                                                     |
| `preflight.mjs`                 | Before each iteration: Docker, Postgres, `gh` and the main checkout; stops the loop with what to do when the machine cannot run one                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `phase-report.mjs`              | When the phase pull request opens: cost, time and review rounds per issue, steward findings, refusals and changed agent memory, with the `retrospective` agent's suggestions                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `run-tools.mjs`                 | What the loop's helpers share: quiet shell calls, session transcripts, asking a tool-less agent                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `steward.mjs`                   | Every 5 minutes during an iteration: gathers facts about the run — health, eval spend against the phase ceiling, paid CI runs, agent usage, review rounds, machine load, free disk, full suites at once — and prints one line, ok, warning or problem; stops the loop at a hard stop (ceiling or cumulative issue stop reached or projected, per-run stop passed, a local phase-pr run, a run of another phase's campaign in the issue's worktree, unexpected paid CI run, disk nearly full at two checks); keeps the paid runs it has seen for the eval runner; asks the `steward` agent when something looks wrong or was paid for, which may stop the loop for inefficient work |
| `worktree.mjs`                  | Creates and removes a worktree per branch with its own slot, ports, database, database role and storage folder; installs, migrates and seeds an empty profile; continues an interrupted issue's unmerged branch when the requested one is cut from a phase branch, and says so (`docs/repository-structure.md`, Ports and worktree isolation)                                                                                                                                                                                                                                                                                                                                      |
| `one-at-a-time.mjs`             | Runs a command under a machine-wide lock in the main checkout's `.worktrees/locks/`: the website's browser tests run one at a time across parallel loops; a stale lock is taken over                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `hooks/`                        | Claude Code hooks: the guard that refuses forbidden actions (a non-draft or state-changed phase pull request and a phase-pr eval run among them), formatting of edited files, the handoff check of developer and general agents, worktree set-up, instructions for compaction and the post-merge reminder                                                                                                                                                                                                                                                                                                                                                                          |
| `git-hooks/`                    | Git hooks (formatting, commit messages) installed by `pnpm install`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `lib/`                          | The pure rules behind them — slots, the loop's decision table, the guard, the steward, eval spend, readiness, progress, the phase report, Windows notifications — with their tests                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `mcp.json`                      | The only MCP servers an unattended run loads                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `setup-github.sh`               | Labels, protection of `master` and Actions opening pull requests; run once by the owner                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

Run a phase (owner only, with Postgres running in the main checkout):

```sh
harness/run-phase.sh <phase-folder> [--base <branch>] [--note "<text for the orchestrator>"]
```
