## Why seven complete slices

Each functional issue has an observable end-to-end outcome, including its contracts/state, implementation, tests/evals, UI where relevant and documentation. There is no separate scaffold-only, security-later or tests-only ticket. S01 is necessarily the first full integration path; it reuses the phase-6 package rather than rebuilding the agent. The remaining slices add complete visitor or owner journeys. Core ownership, one-use grants, bot checks, approved quotas and conservative spend protection apply from the first paid path; S02/S03 extend conformance and visibility instead of introducing safety late.

- **S01 / [#210](https://github.com/sebelapetr/sebela.dev/issues/210):** First real guarded answer and follow-up, browser disconnect/return, identity/persistence, dedicated FastAPI authority, Turnstile, atomic admission/spend, approved progress/cards, generated contracts and container/task/CI integration. A bounded profile capability proves shared-tool parity.
- **S02 / [#211](https://github.com/sebelapetr/sebela.dev/issues/211):** Full cross-tab lifecycle, explicit idempotent retry/Stop/Clear, stale-process recovery and uncertain usage, plus the complete bounded public-read capability handoff for phase 8. No public MCP transport or retrieval is built.

Failures safely degrade to metadata; actual VPS acceptance remains S07.
- **S06 / [#215](https://github.com/sebelapetr/sebela.dev/issues/215):** Private, explicitly budgeted selected-answer grading, annotation-queue/release evidence integration, complete catalogue/workflow wiring and an owner-run acceptance handoff while the final HITL issue remains open.

## Shared implementation and evaluation rules

- Preserve exactly Security -> Main -> deterministic Output. Pseudonymization is a separate telemetry branch and `/compact` a bounded explicit operation, not a fourth answer stage, automatic summary or arbitrary model tool. Only the API reaches Postgres; no Python/web/MCP services/db imports, admin/content-write keys or private-original storage credentials.
- Every new paid operation checks ownership, bot, one-active-operation, quotas, time and atomic spend before work. One async generation process admits four operations, waits at most two seconds and inherits phase 6's 60-second deadline, stage/token/context/tool/retry caps and USD 0.02 ordinary allowance. Quotas remain 5/minute, 10/rolling-two-hours and 30/UTC-day per identity; 20/minute and 100/day per short-lived address fingerprint; runtime spend USD 2/day and USD 20/month. Actual/estimated/uncertain costs stay distinct across cancellation/restart/UTC boundaries.
- Closing a browser stops observation, not generation. Explicit Stop/deletion cancel. Recover stored state before retry; ambiguous process loss never automatically restarts a paid call. One conversation and active chat/compact operation apply across tabs; Clear never resets quotas.
- Per issue run justified affected local paid cases only, with three repeats and recorded scope/cost. Common prompt/context/tool changes can affect phase 6. Full relevant suites run on affected phase PRs into `master` opened/reopened/ready, or explicit manual dispatch; not every push or issue PR. No automatic reference-model sweep.
- Carry the remaining initial USD 10 evaluation-campaign allowance forward across phases, issues, worktrees and CI, including subject/reference/judge/retry/cache/uncertain usage. A new issue does not grant more money. Production selected-answer grading has its own explicit batch allowance. Missing keys, exhausted allowance or unmeasured coverage stay pending rather than PASS.
- Reuse the existing protected secret wrapper, never read/copy owner secrets, preserve compatible saved-answer/no-generation regrade rules and allowlist only redacted report artifacts. Changed model judging can cost money even when generation is reused. Never publish real visitor text or owner data.
- Freeze and verify local masking quality and resource requirements; broad free-text PII detection is best effort. A concrete CPU/ONNX candidate must meet English/Czech and ARM64/CAX21 requirements before content export. Error/timeout/overload or no fitting candidate means metadata-only, not raw/regex-only/remote-GPU export. S07 records actual deployment suitability or the permitted fallback explicitly.
- Langfuse Cloud EU uses actual 30-day linked-content deletion through API-owned references/maintenance; Hobby's access window is not retention. Production code/model/human grading stays separate from the visitor path and does not automatically train models.
- Required deterministic and all critical checks pass; ordinary quality and false blocking meet the PRD's independent EN/CS floors, with honest counts/coverage. Human acceptance is 12 scored answers (6 EN/6 CS) plus every disputed case, not merely a PR approval click.

## Dependency order and final acceptance

S01–S06 form a deliberate sequential chain. They share chat contracts/state/ledger, web adapter/store, FastAPI lifecycle, generated clients, uv lock/configuration and eval/telemetry tooling. Runtime async concurrency does not authorize parallel editing; a new file-ownership plan is required before parallelizing implementation. Seven issues retain those complete behaviours; no extra horizontal setup/security/test tickets are needed.

After prerequisite owner merges, implementation branches/PRs target `phase/07-ai-service`. The owner may start its AFK segment through the existing phase loop; publication does not start it. The loop skips HITL. When AFK work finishes, prepare/open the draft phase PR **with S07 still pending**, then the owner marks it ready or dispatches the full relevant suites, performs human/cloud/VPS acceptance, closes S07 after resolving required gates and finally merges master. Never require S07 closed before the phase PR needed to run its final evals exists. A loop `phase_done`, draft PR, `ready-for-agent` or bare approval is not phase acceptance.

Only S07 is HITL because it requires owner-controlled cloud/VPS access, resource/fallback acceptance and actual human judgment. All code, fake/local tests, detector-selection tooling, private grading commands, maintenance and reviewable reports are AFK work prepared first. Missing paid credentials/budget is reported honestly rather than turning every implementation slice into a manual gate. Production release/DNS/WAF/privacy publication remain phase-10 work; public MCP, RAG, graph, ontology and external MCP UI retain their later phases.
