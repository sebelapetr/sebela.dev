# @sebela/db

PostgreSQL schema, committed migrations and persistence operations. The only package that contains SQL. Read the root `AGENTS.md` first; this file covers only what is specific to this package.

## What it is

A library used only by `@sebela/services`. It may import nothing from this repository except `@sebela/config` (dependency table in `docs/repository-structure.md`). Drizzle tables, query builders, pools and driver errors never leave it: callers receive domain records and documented results.

## Public interface

Only the subpaths declared in `exports` of `package.json` are public.

| Export               | Entry            | What it provides                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@sebela/db`         | `src/index.ts`   | `readDatabaseConfig(env)` (validates `POSTGRES_HOST`, `POSTGRES_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`; no fallbacks), `migrateDatabase(config)`, `createPersistence(config)` returning `{ profile, apiKeys, roadmap, transaction, close }` (`transaction(work)` runs `work` with the profile and roadmap persistence inside one transaction, committed when it resolves and rolled back when it throws; writes that open their own transaction become savepoints), `demoSeedFolder` (the URL of the fictional demo seed in `seed/demo/`, format in `seed/README.md`), and the record types. |
| `@sebela/db/testing` | `src/testing.ts` | Test support only: `createTemporaryDatabase(config, { migrated })` creates a separate `test_<random>` database with the configured role, migrates it unless `migrated: false`, and `drop()` removes it with `DROP DATABASE ... WITH (FORCE)`, retrying without `FORCE` when Postgres refuses it with 42501 (Postgres 18 does so for a non-superuser role while autovacuum runs on the database). Never used by runtime code.                                                                                                                                                                                       |

## Migrations

- Migrations are generated from the schema files and committed in `migrations/` (SQL plus Drizzle's `meta/` journal). Never edit an applied migration; change `schema.ts` and generate a new one.
- Generate: `pnpm --filter @sebela/db db:generate --name <what-changed>`. It needs no database.
- What drizzle-kit cannot express (the exclusion constraint `time_entries_do_not_overlap`) is appended by hand, with a comment, to the newly generated migration before it is committed, and its name is a constant in `schema.ts`. drizzle-kit does not see it, so it never generates a statement that drops it.
- Apply: `pnpm --filter @sebela/db db:migrate`. It builds the package and runs `dist/cli/migrate.js` with the settings of the process environment, then `.env.local`, `.env` and `.env.example` of the checkout (the earlier source wins). It migrates an empty database and does nothing on an up-to-date one. The API never runs migrations when it starts. In the container stack of the main checkout the same `dist/cli/migrate.js` is the one-off service `migrate` of `compose.yaml`, which the API waits for (`apps/api/AGENTS.md`, "Container stack"); the image therefore carries `migrations/` and `seed/demo/` beside `dist/`.
- Each domain gets its own PostgreSQL schema (`profile`, `auth`, `ai_roadmap`). Drizzle records applied migrations in the `drizzle` schema.

## Adding an entity end to end

1. Add the table to the owning module's `schema.ts` and a persistence operation to its `index.ts`, with a test in the module against a temporary database. Generate the migration.
2. Add the service operation in `@sebela/services` (domain rules and errors), then contracts and routes in `@sebela/contracts` and `apps/api`.
3. Update the module maps of every touched package.

## Tests

`pnpm --filter @sebela/db test`. Every test file creates its own temporary database through `createTemporaryDatabase` with the role from the environment (a worktree role has `CREATEDB`), uses small fictional fixtures and drops the database afterwards. Tests need a running Postgres and `DATABASE_USER`/`DATABASE_PASSWORD`; there is no mocked database.
