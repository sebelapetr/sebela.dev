# @sebela/memory

The knowledge and retrieval layer: portfolio ingest, embedding indexing and passage search behind ports. Read the root `AGENTS.md` first; this file covers only what is specific to this package.

## What it is

A library called only by the API backend through `@sebela/services` (dependency table in `docs/repository-structure.md`). It may import `@sebela/contracts` and `@sebela/config` only; it never imports `@sebela/db`. `packages/db` implements its persistence ports and `packages/services` composes it with them and the Voyage adapter (`.plan/09-rag/prd.md`).

Its one outside runtime dependency is the PDF parser `pdfjs-dist`, pinned exactly at 6.5.438 (Apache-2.0 licence, Mozilla). It is plain JavaScript, so it runs unchanged on ARM64 in the API container (checked for #227). Its optional native canvas `@napi-rs/canvas`, used only to render pages, is excluded in `pnpm-workspace.yaml` (`ignoredOptionalDependencies`), because ingest only reads the text layer. A version change of the parser is a reviewed change of this pin.

`@sebela/memory/testing` (`src/testing.ts`) is test support only: `fixturePdf(pages, options?)` builds small deterministic PDFs in memory (lines at a type size, undecodable text, an image, encryption, a script and an outside link as active content) and `malformedPdf()` bytes that start like a PDF. `@sebela/services/testing` re-exports `fixturePdf` for the API's tests. Runtime code never imports it.

## Evals

The retrieval evals live in `evals/` and run with Promptfoo (`docs/testing.md`, Memory evals):

| File                           | What it holds                                                                                                                                                                                                                           |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `datasets/questions.json`      | The fictional EN/CS question set: graded relevance (2/1), canonical paths of judged sources, no-answer questions.                                                                                                                       |
| `datasets/documents/`          | Fictional supplemental documents, including one contradicting an API fact, one with injected instructions and a two-page text-layer PDF.                                                                                                |
| `plan.js`                      | Which cases the system can answer yet (`SEARCHABLE`: the portfolio and the supplemental documents); every other case is pending, never passed.                                                                                          |
| `graders/metrics.js`           | recall@pool, nDCG, precision, MRR, correct/false empty, provenance accuracy, latency percentiles, cost per query.                                                                                                                       |
| `graders/index.js`, `tests.js` | The Promptfoo grader and test generator.                                                                                                                                                                                                |
| `provider.js`                  | The Promptfoo provider: calls the private search route and records each passage's score; never sees the provider's key.                                                                                                                 |
| `run.js`                       | The runner (`pnpm --filter @sebela/memory eval [--case <id>] [--publish <name>] [--max-cost-usd <n>] [--min-interval-ms <n>] [--variant reranked\|hybrid\|vector\|fulltext]`); applies the gate to a complete run of the gated variant. |
| `thresholds.json`              | The frozen gate (recall@pool, nDCG, correct-empty) of the deployed variant it names, with the baselines and the method; deploying another variant switches it; later slices may only raise it.                                          |
| `results/`                     | Published summaries of paid runs.                                                                                                                                                                                                       |

`evals/evals.test.ts` checks the dataset, metrics, plan and options deterministically; it runs with `pnpm test`.
