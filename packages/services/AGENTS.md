# @sebela/services

Domain operations of the backend. Read the root `AGENTS.md` first; this file covers only what is specific to this package.

## What it is

A library used by `apps/api` (HTTP routes and the API-key and seed CLIs). It may import `@sebela/db`, `@sebela/contracts`, `@sebela/memory` and `@sebela/config` (dependency table in `docs/repository-structure.md`). It writes no SQL: it asks `@sebela/db` for persistence operations and never sees a table, query builder or connection.

| `src/modules/storage`  | `src/modules/storage/index.ts`  | `readStorageConfig(env, cwd)` and `openStorage(config)` returning `{ storage, files }`. `Storage` has three operations: `store` (a new file, returns its key), `delete` (a missing file counts as removed) and `publicAddress` (computed from `STORAGE_PUBLIC_BASE_URL`, never stored; `null` for a key this storage cannot address). `files.read` serves local files to the API; `files` is `null` for a driver whose files are served elsewhere. Keys are `<environment>/[<worktree>/]<random uuid>.<png\|jpg\|webp\|pdf>`, generated in private `keys.ts`; a key this storage could not have generated (traversal, another prefix, an absolute path) is refused by `delete`, has no public address and is read as missing. The local driver (private `drivers/local.ts`) resolves the root once, refuses prefix folders that are not real folders, creates files exclusively (`O_EXCL`) and opens them without following links (`O_NOFOLLOW`), so it never writes outside the prefix or replaces a file. The Bunny driver (private `drivers/bunny-s3.ts`) uses `@aws-sdk/client-s3` path-style against the zone's S3 endpoint, signed with the zone name and password; SDK types stay inside the driver. It sends a SHA-256 checksum with every upload, refuses a foreign key before any request, counts a `NoSuchKey` delete as removed and turns SDK failures into plain errors naming the operation and HTTP status, never the password. Its configuration needs `STORAGE_BUNNY_ENDPOINT` (a bare https origin), `STORAGE_BUNNY_REGION`, `STORAGE_BUNNY_ZONE`, `STORAGE_BUNNY_PASSWORD`, an https public base that is not the endpoint host, and `STORAGE_WORKTREE` in `development`; it never falls back to local disk. Configuration errors name variables, never values. `openStorageNamespace(config, owner)` (private `namespace.ts`, with a namespace store per driver in `drivers/`) returns the worktree folder `<environment>/<worktree>/` as a `StorageNamespace`: `prepare` creates it with an owner marker naming `owner` or reuses the folder that owner holds (`created`/`reused`), `remove` deletes every file of the folder only when the marker names the same owner (`removed`/`absent`). It refuses, before touching storage, `production`, a configuration without `STORAGE_WORKTREE` and an invalid owner name, and refuses a folder another owner's marker claims, files without a marker and, on local disk, a prefix folder or marker that is a symbolic link. On Bunny the marker is written without an exclusive create, so two prepares racing for one new folder are not detected. | `src/modules/media`    | `src/modules/media/index.ts`    | `MediaService`: list (newest first), get, upload, update the alt text, delete media and read a recorded local file, returned as the contract `Media` with `url` from `Storage.publicAddress`; a record whose key the configured storage cannot address (another environment or worktree prefix) is still listed and read, with `url: null`, and has no servable file. ## Tests

`pnpm --filter @sebela/services test`. Integration tests against real Postgres: each test file creates its own temporary migrated database through `@sebela/db/testing` with small fictional fixtures. They need a running Postgres and the role in `DATABASE_USER`/`DATABASE_PASSWORD`; see `packages/db/AGENTS.md`. The Bunny storage suite against a real development zone is skipped unless opted in; see `docs/testing.md`.
